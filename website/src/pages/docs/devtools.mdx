Because the simulation never touches the page, the whole game runs in Node:
scripted input in, frames out, as fast as the machine allows. On top of that,
`@typeonce/ritmo-devtools` keeps a trace of every write, so a run can answer
questions in plain text. It is built for coding agents first, and it reads
just as well for people.

```sh
pnpm add -D @typeonce/ritmo-devtools
```

## A scripted run

This script plays the top-down game from the [Examples](/examples/) for 120
frames: it holds up and left, lets go of up at frame 40, and taps interact at
frame 50. An **invariant** is checked after every frame, and the run stops at
the first frame it fails.

```ts twoslash
import { HostClock } from "@typeonce/ritmo"
import { Gamepad, Keyboard } from "@typeonce/ritmo-browser"
import { Invariant, Session } from "@typeonce/ritmo-devtools"
import { PlayerPositionQuery } from "@typeonce/ritmo-integration-top-down/queries.ts"
import { Game, Position } from "@typeonce/ritmo-integration-top-down/schema.ts"
import { createTopDownSimulation } from "@typeonce/ritmo-integration-top-down/simulation.ts"
import { inputBindings, padBindings } from "@typeonce/ritmo-integration-top-down/types.ts"

const keyboard = Keyboard.scripted(inputBindings, [
  { frame: 0, press: ["up", "left"] },
  { frame: 40, release: ["up"] },
  { frame: 50, press: ["interact"], release: ["interact"] }
])

// A test clock keeps every timing at 0, so the output is the same on every run.
const hostClock = HostClock.test()
const gamepad = Gamepad.scripted(padBindings, [])
const simulation = createTopDownSimulation({ keyboard, gamepad, hostClock })
if (!simulation.ok) throw new Error(simulation.error.message)
const { runtime, setup, update } = simulation.value

// Returns a message when the rule is broken, undefined while it holds.
const PlayerInsideWorld = Invariant.fromInspector(
  Game.Inspector("player inside world", { queries: { player: PlayerPositionQuery } }, ({ queries }) => {
    for (const match of queries.player.each()) {
      const { x, y } = match.data.position.get()
      if (x < 0 || x > 2200 || y < 0 || y > 1600) return `player at (${x}, ${y})`
    }
    return undefined
  })
)

const session = Session.make(runtime, {
  hostClock,
  schedules: { setup, update },
  invariants: [PlayerInsideWorld]
})

session.run("setup")
session.run("update", { frames: 120 })
console.log(session.why(1, Position))
```

## Asking why

`session.why(entity, Component)` prints the latest changes to a value and the
system that made each one. For the run above:

```text
e1 TopDown/Position is now {x:134.673,y:128.007}; last 5 changes (oldest first):
could have spawned it: TopDown/SetupWorld
f117 update  TopDown/MovePlayer  write e1 TopDown/Position {x:158.007,y:128.007} -> {x:153.34,y:128.007}
f118 update  TopDown/MovePlayer  write e1 TopDown/Position {x:153.34,y:128.007} -> {x:148.673,y:128.007}
f119 update  TopDown/MovePlayer  write e1 TopDown/Position {x:148.673,y:128.007} -> {x:144.007,y:128.007}
f120 update  TopDown/MovePlayer  write e1 TopDown/Position {x:144.007,y:128.007} -> {x:139.34,y:128.007}
f121 update  TopDown/MovePlayer  write e1 TopDown/Position {x:139.34,y:128.007} -> {x:134.673,y:128.007}
```

The other questions work the same way:

| Call | Answers |
|---|---|
| `session.describe()` | The schema, every schedule step, and who reads and writes each component, resource, and event, with lints first |
| `session.report()` | Warnings, time per system, and how many entities have each component |
| `session.dump({ with: [Player] })` | The entities, resources, and state machines right now |
| `session.whyResource(Score)` | The latest changes to a resource |
| `session.journal({ frames: [100, 120], entity })` | Everything that touched an entity in a range of frames |

## Lints

`session.describe()` and `session.report()` start with **lints**: things that
compile but are probably wrong, like an event nobody reads, a state no
schedule ever applies, or a system that reads a value before the schedule's
first writer (a one-frame lag). For the run above:

```text
# Lints
info command-permission-unused: TopDown/CollectFocusedCollectable may despawn TopDown/Collectable but never did in this session
```

Two commands put these checks in a game's `check` script, next to the type
check and the tests:

- `ritmo-devtools lint src/simulation.ts` prints every lint of the game's
  schedules with its fix, and fails on a warning.
- `oxlint` with `@typeonce/oxlint-plugin-ritmo` rejects what types cannot
  see in simulation code: the wall clock, `Math.random`, `Math.sin`, the page,
  and dropped tick results. Each message names the API to use instead.

## Same input, same game

`Determinism.check` runs the same scripted simulation twice and compares
every value of every frame. A difference reports the frame, the value, and
the first system that diverged. With the lint rules keeping time, randomness,
and maths deterministic, a recorded play session replays exactly, and a bug
found once becomes a test that stays fixed.
