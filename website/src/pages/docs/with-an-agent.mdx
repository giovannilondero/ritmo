Ritmo is agent-first: you direct the game (the mechanics, the feel, what is
fun) and a coding agent writes the simulation. The library's job is to keep
the agent on track, and it does that in three layers:

1. **Wrong code does not compile**, and the error names the fix (see
   [Type safety](/docs/type-safety/)). An agent reads the error, applies the
   fix, and moves on, without guessing.
2. **Headless runs explain themselves.** The agent plays the game in Node
   with scripted input, checks invariants every frame, and asks why a value
   changed (see [Headless debugging](/docs/devtools/)).
3. **Every bug becomes a test.** The script that reproduced a bug turns into
   a test next to the game, so the same mistake fails loudly next time.

## Set up a project

Paste this into your coding agent in the game's folder, then describe the
game you want:

```text
Set up Ritmo in this project by following
https://raw.githubusercontent.com/typeonce-dev/ritmo/main/packages/core/SETUP.md
```

The setup installs the packages and the checks every Ritmo game uses (the
type check, the lint rules, `ritmo-devtools lint`, and the tests), and links
the **Ritmo skill** into the agent's skills folder.

## The skill

The skill ships inside `@typeonce/ritmo`, so it always matches the installed
version. On every change the agent reads it, picks the playbook for the kind
of change (a mechanic, content, UI and rendering, a bug fix, a refactor, saves
and upgrades), and follows its steps and its check.

It also holds the few principles that keep a game easy to change:

- **The simulation is the game; everything else is a host.** Rules are
  systems. Input, drawing, UI, storage, and sound are host code.
- **Intents in, plain data out.** Player actions arrive as typed intents, and
  UIs read the world as plain data. Bots, tests, and replays send the same
  intents as the UI.
- **Each fact has one home.** A closed set (items, enemies, buildings) is
  defined once, and every table that must cover it fails to compile when an
  entry is missing.
- **Make the next mistake fail loudly.** A rule that can be a type, a lint,
  or a test becomes one.

## Where the agent reads

This site is for people. The agent reads what ships with the packages: the
JSDoc on every export, each package's README, its CHANGELOG (breaking entries
name their fix), and the skill. Those always match the version installed in
the game, which a website cannot promise.
