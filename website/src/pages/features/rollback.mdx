Online games hide latency with rollback: run every tick at once with a
guess for the other player's input, and when their real input arrives and
differs, go back to the tick it was for and run again up to now. That takes
a simulation that plays the same on every machine (Ritmo's
[determinism](/features/determinism/)), and a way back that puts the world
exactly where it was.

Both views are peers of one match, each with its own runtime, over a fake
network with the latency picked in the corner. Your moves reach the other
peer late; it rolls back, runs the ticks again, and the two agree on every
tick they compare.

## Checkpoints

`runtime.checkpoint(simulate)` marks the world between ticks;
`runtime.rewind(checkpoint)` puts it back. Ticking `simulate` again then
gives the same results, bit for bit, as a runtime that never went back:
the same entity ids, values, relations, queued commands, unread events,
machine states, and every system's read positions.

```ts twoslash title="rollback.ts"
import { Checkpoint, Descriptor, Schema } from "@typeonce/ritmo"
const Root = Schema.defineRoot("Game")
const Score = Descriptor.Resource<number>()("Game/Score")
const Game = Schema.bind(Schema.fragment({ resources: { Score } }), Root)
const simulate = Game.Schedule()
const runtime = Game.Runtime.make({ services: Game.Runtime.services(), resources: { Score: 0 } }).value!
declare let tick: number
declare const wrongTick: number
declare const resync: (error: Checkpoint.RewindError) => void
// ---cut---
const history = new Map<number, Checkpoint.Checkpoint<typeof Root>>()

// Every tick: keep where it starts, then run it with the input known so far.
history.set(tick, runtime.checkpoint(simulate))
runtime.tick(simulate)

// Real input for an earlier tick differs from the guess: go back, run again.
const rewound = runtime.rewind(history.get(wrongTick)!)
if (!rewound.ok) resync(rewound.error) // older than the window: load a save
else for (let at = wrongTick; at <= tick; at++) {
  history.set(at, runtime.checkpoint(simulate))
  runtime.tick(simulate)
}
```

A checkpoint copies almost nothing when it is taken. The first change to a
page of values, an entity, or a relation after it keeps what it replaced,
so a tick costs what it changes, not what the world holds.

## What cannot be rewound does not compile

A rewind runs ticks again, so whatever they call runs again. A service
that plays a sound would play it once for every tick run again, and state
a system keeps in `local` would not come back. `checkpoint` checks the
schedule, its state transitions included:

```ts twoslash
import { Descriptor, Schema } from "@typeonce/ritmo"
const Game = Schema.bind(Schema.fragment({}))
const Sound = Descriptor.Service<{ readonly play: (name: string) => void }>()("Game/Sound")
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Sound, { play: () => {} })) }).value
// ---cut---
const Hit = Game.System("Game/Hit", { services: { sound: Game.System.service(Sound) } }, ({ services }) => {
  services.sound.play("hit")
})

// @errors: 2379
runtime.checkpoint(Game.Schedule(Hit))
```

Input comes in through a source the host fills for each tick, and effects
leave through events and resources that host code acts on.

## The screen sees one change

Rendering runs outside the rewound schedule, so it never goes back. It
sees a rollback the way it sees any tick: a value that moved, an entity
that is gone, one that appeared. A shot the rewind took away and the ticks
after it brought back, under the same id, is a shot that moved: its sprite
stays where it is, never destroyed and made again.

## Checking that peers agree

`runtime.checksum()` is a fingerprint of the world that does not depend on
how it was built, the same on every device. Peers exchange the checksums
of confirmed ticks, and a desync shows up the tick it happens:

```ts twoslash
import { Descriptor, Schema } from "@typeonce/ritmo"
const Score = Descriptor.ConstructedResource({ "~standard": { version: 1, vendor: "example", validate: (value: unknown) => ({ value: value as number }) } })("Game/Score")
const Game = Schema.bind(Schema.fragment({ resources: { Score } }))
const made = Game.Runtime.make({ services: Game.Runtime.services(), resources: { Score: 0 } })
if (!made.ok) throw new Error("invalid")
const runtime = made.value
declare const theirs: string
declare const reportDesync: () => void
// ---cut---
const mine = runtime.checksum()
if (mine.ok && mine.value !== theirs) reportDesync()
```

## Over the network

`@typeonce/ritmo-netcode` puts it together: one session per peer exchanges
inputs, takes the checkpoints, rolls back, slows the peer that runs ahead,
and compares checksums. The game gives it the simulation, the seats, and a
link; here the input schema is Effect's.

```ts twoslash title="online.ts"
import { Clock, Descriptor, FixedLoop, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], encode: S.toStandardSchemaV1(S.flip(json)) }
}
import { BrowserHostClock, BrowserTickSource, InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, WebSocketNetworkLink } from "@typeonce/ritmo-netcode"
const step = Clock.hz(60)
declare const socket: WebSocket
declare const readInput: () => PlayerInput
declare const showDisconnected: (failure: unknown) => void
// ---cut---
const PlayerInput = S.Struct({ dx: S.Literals([-1, 0, 1]), fire: S.Boolean })
type PlayerInput = typeof PlayerInput.Type

// The simulation reads every seat's input from one source.
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
const simulate = Game.Schedule(Capture)

const seats = Netcode.seats(codec(PlayerInput), { count: 2, idle: { dx: 0, fire: false } })
if (!seats.ok) throw new Error(seats.error.reason)
const runtime = Game.Runtime.make({
  services: Game.Runtime.services(Game.Runtime.service(Seats, seats.value.source)),
  resources: { Inputs: [] }
}).value

const session = Netcode.rollback(runtime, {
  simulate,
  seats: seats.value,
  seat: 1, // seat 0 hosts: every peer starts from its world
  links: [WebSocketNetworkLink.make(socket)],
  hostClock: BrowserHostClock.make(window),
  step
})
if (!session.ok) throw new Error(session.error.reason)

FixedLoop.start({
  source: BrowserTickSource.make(window), step, maxFrameSeconds: 0.25, maxStepsPerFrame: 5,
  rate: session.value.rate,
  update: session.value.update({ input: readInput, onHalted: (error) => console.error(error) }),
  render: () => {},
  onFailure: showDisconnected
})
```

What cannot work does not compile: a simulation that cannot be rewound,
one whose services the runtime does not provide, a runtime that cannot
save. A checksum that differs stops the session and reports it; a resync
starts every peer again from seat 0's world.

Ritmo carries no server: a link wraps a connection the game opened, a
WebSocket to a relay, a WebRTC data channel between peers, or any
transport with `send`, `receive`, and `status`.
