Every peer runs the same simulation, on its own machine.

They send each other only their input.

When a player's input arrives late, the others roll back to the tick it was for, and run again up to now.

Both views are peers of one match, each with its own runtime.

They talk over a fake network, with the latency picked in the corner.

Your moves reach the other peer late: it rolls back, runs the ticks again, and the HUD counts it.

## Online multiplayer

`@typeonce/ritmo-netcode` gives every peer a session.

The session exchanges inputs, takes the checkpoints, rolls back, and keeps the peers in step.

The game gives it three things: where input comes from, the simulation, and a connection.

### 1. Input comes from one source

The simulation never sees the network.

It reads every seat's input for the tick from one source, like any other input.

The input's schema is the game's own: Effect's here, any Standard Schema works.

```ts twoslash title="input.ts"
import { Descriptor, Schema } from "@typeonce/ritmo"
import { Schema as S } from "effect"
const codec = <T extends S.Top & { readonly DecodingServices: never; readonly EncodingServices: never }>(schema: T) => {
  const json = S.toCodecJson(schema)
  return { "~standard": S.toStandardSchemaV1(json)["~standard"], encode: S.toStandardSchemaV1(S.flip(json)) }
}
import { InputCapture } from "@typeonce/ritmo-browser"
import { Netcode } from "@typeonce/ritmo-netcode"
// ---cut---
const PlayerInput = S.Struct({ dx: S.Literals([-1, 0, 1]), fire: S.Boolean })
type PlayerInput = typeof PlayerInput.Type

// Every seat's input for the tick being run.
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats") // [!code highlight]
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")

const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })

// The schedule every peer ticks the same way.
const simulate = Game.Schedule(Capture /* , Move, Fire, ... */)

// Two seats. Input from another peer is decoded with the schema.
const seats = Netcode.seats(codec(PlayerInput), { count: 2, idle: { dx: 0, fire: false } }) // [!code highlight]
if (!seats.ok) throw new Error(seats.error.reason)

const runtime = Game.Runtime.make({
  services: Game.Runtime.services(Game.Runtime.service(Seats, seats.value.source)), // [!code highlight]
  resources: { Inputs: [] }
}).value
```

Remote input never goes through `runtime.send`: a rollback would read it on the wrong tick.

### 2. A session per peer

Pick the model:

- `Netcode.rollback` runs every tick at once, guessing input that has not arrived. For real-time games: input feels immediate.
- `Netcode.lockstep` waits for every seat's input. For turn-based games: nothing ever runs twice.

```ts twoslash title="session.ts"
import { Clock, Descriptor, Schema } from "@typeonce/ritmo"
import { BrowserHostClock, InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, WebSocketNetworkLink } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
const simulate = Game.Schedule(Capture)
declare const seats: Netcode.Seats<PlayerInput>
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Seats, seats.source)), resources: { Inputs: [] } }).value
const step = Clock.hz(60)
// ---cut---
// A WebSocket the game opened, to a relay that forwards to the other peers.
const socket = new WebSocket("wss://relay.example.com/match/42")

const session = Netcode.rollback(runtime, {
  simulate,
  seats,
  seat: 1, // seat 0 hosts: every peer starts from its world
  links: [WebSocketNetworkLink.make(socket)], // [!code highlight]
  hostClock: BrowserHostClock.make(window),
  step
})
if (!session.ok) throw new Error(session.error.reason)
```

Ritmo carries no server.

A link wraps a connection the game opened:

- `WebSocketNetworkLink`: a relay, from the browser, Node, Deno, or Bun.
- `WebRtcNetworkLink`: a data channel, straight between peers.
- Anything else: implement `send`, `receive`, and `status`.

### 3. The loop drives it

Each step, the session reads the network, rolls back if a guess was wrong, ticks, and sends.

```ts twoslash title="loop.ts"
import { Clock, FixedLoop } from "@typeonce/ritmo"
import { BrowserTickSource } from "@typeonce/ritmo-browser"
import type { Netcode } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
declare const session: Netcode.Session<PlayerInput, never>
declare const readInput: () => PlayerInput
declare const draw: () => void
declare const showDisconnected: (failure: unknown) => void
const step = Clock.hz(60)
// ---cut---
FixedLoop.start({
  source: BrowserTickSource.make(window),
  step,
  maxFrameSeconds: 0.25,
  maxStepsPerFrame: 5,

  // Slows this peer while it runs ahead of the others.
  rate: session.rate, // [!code highlight]

  // Advances the session with this seat's input, once per step.
  update: session.update({ // [!code highlight]
    input: readInput,
    // A desync is a bug in the game: log it. The session resyncs on its own.
    onHalted: (error) => console.error(error)
  }),

  // Drawing runs outside the simulation, so it never rolls back.
  render: draw,

  // The session ended: a peer left, or runs another version.
  onFailure: showDisconnected
})
```

## What cannot work does not compile

A rollback runs ticks again, so whatever they call runs again.

A sound would play once per rollback. State a system keeps in `local` would not come back.

The session checks the simulation, its state transitions included:

```ts twoslash
import { Clock, Descriptor, HostClock, Schema } from "@typeonce/ritmo"
import { InputCapture } from "@typeonce/ritmo-browser"
import { Netcode, type NetworkLink } from "@typeonce/ritmo-netcode"
interface PlayerInput { readonly dx: number; readonly fire: boolean }
const Seats = Descriptor.Service<Netcode.Source<PlayerInput>>()("Game/Seats")
const Inputs = Descriptor.TransientResource<InputCapture.SnapshotOf<typeof Seats>>()("Game/Inputs")
const Game = Schema.bind(Schema.fragment({ resources: { Inputs } }))
const Capture = InputCapture.system(Game, { name: "Game/Capture", source: Seats, resource: Inputs })
declare const seats: Netcode.Seats<PlayerInput>
declare const link: NetworkLink.NetworkLink
const runtime = Game.Runtime.make({ services: Game.Runtime.services(Game.Runtime.service(Seats, seats.source)), resources: { Inputs: [] } }).value
const options = { seats, seat: 0, links: [link], hostClock: HostClock.standard, step: Clock.hz(60) }
// ---cut---
const Combo = Game.System("Game/Combo", { local: () => ({ hits: 0 }) }, ({ local }) => {
  local.hits++
})

// @errors: 2375
Netcode.rollback(runtime, { ...options, simulate: Game.Schedule(Capture, Combo) })
```

So does a runtime that cannot save, and a simulation whose services the runtime does not provide.

## Peers agree, or say so

Every 30 ticks, peers compare a checksum of a tick every seat's real input reached.

A mismatch stops the session with `Desynced`, and a resync starts every peer again from seat 0's world.

`status()` says how far they agree, for a HUD or a test:

```ts twoslash
import type { Netcode } from "@typeonce/ritmo-netcode"
declare const session: Netcode.Session<unknown, never>
// ---cut---
const { tick, confirmed, verified, rollbacks } = session.status()
```

## Under the hood: checkpoints

A session rolls back with the runtime's own checkpoints, which a game can also use directly (an undo, say).

`runtime.checkpoint(simulate)` marks the world between ticks.

`runtime.rewind(checkpoint)` puts it back: ticking again gives the same results, bit for bit, as a runtime that never went back.

```ts twoslash title="rollback.ts"
import { Checkpoint, Descriptor, Schema } from "@typeonce/ritmo"
const Root = Schema.defineRoot("Game")
const Score = Descriptor.Resource<number>()("Game/Score")
const Game = Schema.bind(Schema.fragment({ resources: { Score } }), Root)
const simulate = Game.Schedule()
const runtime = Game.Runtime.make({ services: Game.Runtime.services(), resources: { Score: 0 } }).value!
declare const wrongTick: number
// ---cut---
const history = new Map<number, Checkpoint.Checkpoint<typeof Root>>()

// Before each tick: keep where it starts.
history.set(0, runtime.checkpoint(simulate)) // [!code highlight]
runtime.tick(simulate)

// Later: go back, and run again from there.
const rewound = runtime.rewind(history.get(wrongTick)!) // [!code highlight]
if (!rewound.ok) console.error(rewound.error) // older than the checkpoints kept
```

A checkpoint copies almost nothing when it is taken.

The first change to a page of values, an entity, or a relation keeps what it replaced, so a tick costs what it changes.

## The screen sees one change

Rendering runs outside the simulation, so it never goes back.

It sees a rollback like any tick: a value that moved, an entity that is gone, one that appeared.

A shot the rollback took away and brought back is a shot that moved: its sprite stays, never destroyed and made again.
